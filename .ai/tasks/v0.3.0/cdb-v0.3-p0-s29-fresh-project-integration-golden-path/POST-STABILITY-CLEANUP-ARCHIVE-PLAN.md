# 版本稳定后的旧代码与历史内容清理归档计划

日期：2026-10-12。
状态：PLANNED / POST-STABILITY FOLLOW-UP。
来源：用户要求在版本稳定后清理归档旧代码、历史内容，减少开发干扰。
本记录授权范围仅为登记计划；当前不执行迁移、删除、源码重构或真实状态清理。

## 目标与优先级

当前版本的正常使用、准入与验收优先。旧内容按其对当前版本的实际影响分类，
避免历史诊断、过时入口和无效引用持续干扰开发判断。

已验证有效保留处置、无当前运行影响且不会被新操作采用的旧 candidate，
应作为历史提示与后续清理项；仍活跃、影响共享资源或无法证明隔离的内容，
继续按原安全边界处理。不能仅凭旧 generation、文件年龄或原 action 缺失忽略它。
Manager 与后端如何一致识别有效保留处置仍在分析，本计划不将其标为已实现。

## 启动条件

1. 用户明确接受当前目标版本为稳定检查点，记录 exact source/package 身份。
2. 目标版本约定的核心流程已通过相应验收；未完成路线与延期项明确记录。
   当前三项 Manager/页签/Unity 关闭结果不单独构成版本稳定判定，S29/release 仍为 PARTIAL。
3. 先完成依赖与引用盘点，再冻结本轮 keep/archive/remove 清单及验证范围，
   由用户授权具体执行。它不要求先关闭所有历史事项，也不作为当前验收的新门槛。

## 计划范围

| 内容 | 处理方向 |
| --- | --- |
| 被替代的旧代码、临时补丁、重复测试工具 | 核对调用方与支持契约；移除确已无用的部分，保留必要兼容与回归覆盖 |
| 历史任务、诊断、交接、过时操作说明 | 建立当前入口和历史索引，标明 superseded 关系，归档详细过程并维护链接 |
| 旧包、验证输出、备份、废弃验证工程 | 核对 manifest/lock、消费方引用和恢复用途，按保留策略归档；产物与备份留在仓库本地约定根目录 |
| 旧 candidate、receipt、removal intent、运行时历史 | 单独盘点其处置与共享资源依赖；物理清理另行冻结权限与范围，不与文档归档或代码整理混为一项 |

## 执行与完成证据

- 每个目标记录原路径、保留/归档/移除理由、引用方、支持或恢复责任及目标位置。
- 归档保留原结果和必要身份、hash、映射；更新当前文档入口与引用，不把历史失败改写为成功。
- 按冻结清单小批处理，保留可恢复检查点及用户 dirty/untracked 状态。
- 对删除旧代码执行直接相关的编译/回归检查；对文档归档检查链接；对产物整理检查消费引用。
  真实 runtime 清理使用其独立处置与验收流程。
- 完成后当前开发入口只引导到有效代码、契约和验收说明；历史证据可追溯，
  仍需保留的兼容路径和延期项有明确归属。

本计划未创建远端 GitHub Project 任务，未 commit/push，也未进行任何清理。
