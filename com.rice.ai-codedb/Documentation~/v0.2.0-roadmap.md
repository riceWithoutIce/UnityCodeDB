# UnityCodeDB v0.2.0 Roadmap

Status: approved for implementation.

## Summary

Problem: normal CodeDB use must stay current without manual refresh, return
strictly bounded source context, respect search scopes, and avoid multiplying
provider query processes across MCP connections.

Current baseline: every MCP stdio connection owns a lightweight Node wrapper.
Provider-routed calls start one short-lived `codebase-mcp` process, while an
explicitly enabled project coordinator separately owns the persistent watch
provider and Shader/HLSL adapter worker.

Decision: automatic refresh becomes the normal post-setup state. Keep one
stdio wrapper per MCP connection, and extend the existing project coordinator
as the authenticated shared query backend. Do not fork the provider, add a
second daemon, or add implicit request batching in this release.

## Candidate Matrix

| Candidate | Multi-session reuse | New dependency | Project isolation | Main risk | Decision |
| --- | --- | --- | --- | --- | --- |
| Keep one-shot provider calls | None | No | Existing | Repeated process startup and blocking | Reject |
| Persistent provider per wrapper | Per connection only | No | Existing | Duplicates provider processes across sessions | Reject |
| Add a separate query daemon | Project-level | No | Must be rebuilt | Duplicates coordinator lifecycle and recovery | Reject |
| Extend the existing coordinator | Project-level | No | Existing runtime, pipe, lease, and token | Expands a proven protocol | Approve |

## Hard Gates

| Gate | Result | Evidence |
| --- | --- | --- |
| Target environment support | Pass | Existing coordinator lifecycle is validated on Unity 2022.3 and Windows. |
| Supported distribution/build path | Pass | Reuses tracked Node source and the existing package payload; no build or download is added. |
| Scoped generated data | Pass | State, logs, sockets, indexes, and markers stay under ignored project-local runtime. |
| Ignore and isolation behavior | Pass | The runtime is project-slugged and guarded against paths outside the Unity root. |

| Baseline advantage | Pass | Removes per-call provider startup from the normal watched path and enables cross-session single-flight execution. |

## Product Contract

- Initial host-file materialization, provider installation, and runtime setup
  remain explicit operations.
- Once provider and both discovery indexes are ready, automatic refresh is
  enabled and recovered without requiring manual Refresh.
- The tracked formal provider config remains `watch=false`; the coordinator
  owns a generated watch-enabled sibling config.
- Pausing automatic refresh is explicit and persistent. Manual Refresh remains
  a maintenance and recovery action.
- `codedb_read` returns only the requested bounded source window.
- Search scope aliases are normalized before routing, and merged results obey
  one global result and output limit.
- One project coordinator may serve many wrappers. Wrapper count follows MCP
  connection count, but provider/watch ownership does not.

## POC Plan

Hypothesis: the existing coordinator can proxy authenticated provider
`tools/call` requests over its local pipe while preserving project isolation,
watch recovery, and bounded output.

Scope: add one read-only query command to the existing pipe protocol, route
provider calls through it while the coordinator is ready, retain the one-shot
fallback while automatic refresh is paused, and add timing diagnostics.

Generated data and cleanup: only ignored coordinator state and logs change.
The existing guarded Stop path remains the rollback and cleanup mechanism.

Validation: direct wrapper fixtures, three concurrent wrappers, provider crash
recovery, automatic C# and Shader/HLSL updates, Domain Reload, Editor restart,
Project A/B isolation, and local/file/Git package tests.

Stop condition: reject the proxy integration if it can escape the Unity root,
serve a request without the coordinator token, corrupt shared index state,
break guarded Stop/recovery, or regress the one-shot fallback.

## Delivery Sequence

1. Make automatic watch the normal post-setup state with explicit Pause/Resume.
2. Enforce bounded reads and wrapper-owned output ceilings.
3. Normalize scoped search routing, merge, deduplication, and limits.
4. Add provider, queue, and end-to-end timing evidence.
5. Add the coordinator query proxy and multi-session single-flight handling.
6. Complete lifecycle acceptance and publish `v0.2.0`.
