# UnityCodeDB v0.2.5 Validation Roadmap

Status: `v0.2.5-preview.1` prepared for third-party legacy Redeploy validation.
The two environment-dependent items remain `DEFERRED / ACCEPTED RISK`, not
passed release evidence.

## Decision Record

The v0.2.4 preview cycle passed its executed third-party matrix without
a new P0 or P1 product defect. Product ownership explicitly accepted deferring
two environment-dependent live checks so the stable 0.2.x line could ship:

1. concurrent isolation between two independently configured Unity projects;
2. an Elevated Unity Editor queried by a NotElevated Codex/MCP client.

These gaps do not retroactively fail v0.2.4, but stable documentation and
release notes must not claim either matrix passed. A discovered defect belongs
in the v0.2.x lifecycle line before related support claims expand.

## Legacy Host Redeploy Validation

`v0.2.5-preview.1` adds a controlled stopped-owner Redeploy path for the
published `poc.9`, `poc.16`, and `poc.20` flat Host identities. Third-party
acceptance must verify that active MCP/watcher owners block without writes,
then that Redeploy publishes `poc.28` and regenerates the ignored runtime config
while preserving Provider binaries, indexes, adapters, MCP registration,
unowned files, business Assets, and Git staging.

## Live Two-Project Concurrency

Use two independent canonical Unity roots, each with stable package identity,
project-local Setup, Provider runtime, MCP registration, and unique C#/Shader
sentinel content. Run both Editors and MCP clients concurrently.

Acceptance:

- roots, runtime slugs, updater locks, leases, pipes, configs, and backend
  processes remain project-local;
- each client returns only its own project content, including during concurrent
  status/search/read requests;
- Stop, close, and reopen in one project do not restart, block, or contaminate
  the other;
- both projects recover to Ready without global registration, process
  termination, or manual PID/lease cleanup.

Do not force two interactive Editors to open the same Unity-locked project.
If no second qualified project exists, record `BLOCKED`, never `PASS`.

## Elevated Unity With NotElevated MCP

Launch Unity elevated through an explicit user-operated UAC action while the
Codex/MCP client remains non-elevated. Record elevation and project identity
without exposing pipe authentication material.

Acceptance:

- a Ready coordinator remains queryable over the authenticated project-local
  pipe;
- permission-limited PID metadata is indeterminate rather than a false host
  block, stale state, or Editor-offline result;
- status, exact and regex C# search, bounded read, context, and Shader/HLSL
  search pass without one-shot fallback or elevated Codex;
- disabled and Editor-offline queries keep zero Provider attempts.

UAC remains user-operated. If the matrix cannot be established, record
`BLOCKED` or `DEFERRED`, never `PASS`.

## Delivery

- GitProject: `[P1] UnityCodeDB v0.2.5: live two-project concurrency isolation`.
- GitProject: `[P1] UnityCodeDB v0.2.5: Elevated Unity with NotElevated MCP regression`.
- Keep both tasks in Backlog until an environment and operator are available.
- If both pass, close the validation debt without inventing a behavioral
  package change. If either fails, implement and release the narrow v0.2.x fix
  with its own immutable generation and regression coverage.

## Non-Goals And Safety

- No v0.3.0 navigation expansion, global daemon, or global MCP registration.
- Do not weaken root, ownership, process identity, lease, pipe authentication,
  or response-bound checks to make a matrix pass.
- Do not commit credentials, tokens, Provider binaries, private machine paths,
  runtime reports, or machine-local configuration.
