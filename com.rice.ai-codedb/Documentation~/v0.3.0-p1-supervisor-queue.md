# v0.3.0 P1-A: Supervisor Request Queue

Status: active development slice; not release evidence.

## Purpose

The v0.3 runtime already has an asynchronous, authenticated Supervisor Bridge,
but lifecycle reconcile, reconnect, and Manager-triggered observations can still
enter through separate paths. P1-A adds one bounded admission queue before those
paths reach the project-local runtime. It is intended to prevent duplicate
startup/reconcile work and stale results during Play and Domain Reload.

## Scope

- status observations and Supervisor reconnects use query priority;
- reconcile and other heavy lifecycle work use the maintenance lane;
- one maintenance request is admitted at a time;
- duplicate requests with the same operation key are coalesced;
- requests left behind by an older epoch are canceled and never reused by a
  same-key request;
- Play, compilation, and Domain Reload advance an epoch and cancel stale work;
- late results from an older epoch cannot complete the current request;
- queue admission and Bridge calls remain asynchronous and do not perform work
  on the Unity callback thread;
- the existing `poc.33` Host generation remains byte-exact and is not rewritten.

The existing background scheduler remains responsible for process-cancellation
tokens and the lightweight Editor lease lane. This slice does not move the
materializer or Provider implementation into a new Host generation.

## Follow-up Boundary

P1-B will make the external Supervisor the complete command owner, migrate the
Manager reducer to cached Supervisor snapshots/events, and add fresh Unity
instrumentation proving zero CodeDB filesystem, hash, process, lock, or
synchronous IPC work on the Unity main thread. Discover Read expansion is later.

## Safety Invariants

- external MCP/client processes are never stopped by queue cancellation;
- queue cancellation only cancels CodeDB-owned admission/work tokens;
- immutable instance/control, ownership, reparse, lease, and rollback rules are
  unchanged;
- `Ready` still requires the verified usable path; missing machine prerequisites
  remain a distinct `Missing prerequisite` result.

## Focused Acceptance

1. Query observations are selected before pending maintenance.
2. Same-key observations execute once and share the result.
3. A boundary cancels active and pending maintenance without blocking the
   callback that raised the boundary.
4. An invalidated epoch rejects a late result.
5. Lifecycle reconnect and reconcile route through the queue, while Manager
   explicit refresh uses the lifecycle worker after initialization.
6. Package boundary and C# lifecycle tests prove the queue is present and no
   `poc.33` payload bytes changed.

Fresh Unity, real Supervisor IPC, real Codex Desktop tool injection, and
third-party Package-only acceptance remain `BLOCKED`/`DEFERRED` until P1-B and
the corresponding local environments are available.
