# v0.3.0 P0: Supervisor Runtime Ownership And Crash Recovery

Status: implementation snapshot; focused automated evidence is recorded below,
but this document does not claim release acceptance.

## Why This Task Exists

The current v0.3 Supervisor implementation separates state publication, process
checking, pipe connection, lock acquisition, and lifecycle retry across Bridge,
Supervisor, Coordinator, and Unity. Each piece is locally reasonable, but the
combined failure path is not recoverable:

1. The Supervisor state may be published before its pipe is listening.
2. A Windows replacement can fail with `EPERM` when a reader denies delete
   sharing. The current Supervisor writer has a delete-then-move fallback and
   no durable recovery boundary for that failure.
3. A Supervisor that exits can leave `supervisor-state.json` and
   `supervisor.lock`. The Bridge sees the state file and tries the old pipe,
   while a new daemon sees the lock and exits.
4. Coordinator stale recovery uses PID existence as the first owner decision.
   Provider and adapter cleanup has command-line checks but does not bind every
   child to its recorded process-start identity.
5. Supervisor operations are primarily held in an in-memory map. A crash can
   leave a child operation without enough durable evidence for a new Supervisor
   to attach or safely decide whether to retry.
6. Lifecycle callers can resubmit failed `Upgrade`/`Probe` work before the
   runtime owner has been classified, creating a retry storm and more state
   publication contention.

The result is normal-path unavailability, not merely a diagnostic display
problem. The downstream Manager `Needs attention` state is addressed only after
the owner and recovery contract is corrected.

## Scope

### 1. Shared Runtime Evidence Contract

Define one versioned evidence model for Supervisor, Coordinator, and owned
children:

- canonical project root, selected instance, runtime, and generation contract;
- PID and process-start identity;
- exact executable and normalized argv (or a reviewed immutable argv hash);
- owner epoch/lifecycle identity;
- pipe name and independent authentication token;
- admitted operation identity and child-process evidence;
- publication phase and last durable update.

The classifier returns only:

`MISSING`, `STARTING_OWNED`, `LIVE_AUTHENTICATED`, `STALE_PROVED`, or
`INVALID_OR_AMBIGUOUS`.

An absent process proves stale only when the recorded evidence is otherwise
well-formed. A live PID with an unreadable identity is ambiguous. A malformed,
redirected, or conflicting state file is not treated as a missing file.

### 2. Hierarchical Startup And Takeover

- Bridge first classifies the Supervisor state and lock; it does not connect to
  an unverified stale pipe.
- A live authenticated Supervisor is reused without a second backend start.
- A bounded startup window is represented as `STARTING_OWNED`, including the
  intentional interval between state publication and pipe listen.
- A proven stale owner is atomically claimed/quarantined and then relaunched.
  Two simultaneous starters cannot both claim the same stale evidence.
- A live or ambiguous owner is never removed merely because a lock is old.
- Coordinator recovery is initiated by the Supervisor. The Coordinator no
  longer makes an independent PID-only stale-owner decision on the normal v0.3
  route.

### 3. Windows-Safe State Publication

All mutable control JSON follows one publication helper:

- strict UTF-8 without BOM;
- unique temporary file;
- complete write and flush before replacement;
- atomic replacement with bounded retry for transient Windows sharing;
- no delete-then-move gap;
- explicit terminal error when replacement cannot be proven.

Readers must allow replacement of an already-open old file while retaining a
consistent snapshot. A failed publication must not crash the runtime through an
uncaught promise rejection or silently leave a state that claims progress it
did not durably record.

### 4. Operation Crash Recovery

Every admitted maintenance operation records a durable operation identity,
phase, child PID/start identity, exact command identity, and result location.
After Supervisor loss:

- an exact live child is observed and awaited, never duplicated;
- a materializer child is reconciled with its transaction journal and active
  marker before any retry;
- an exited child is verified through the authoritative project state before a
  terminal result is recorded;
- missing or ambiguous child evidence blocks safely rather than triggering a
  blind rerun.

The operation protocol remains bounded per IPC exchange. Long-running work is
not kept on an open Bridge request.

### 5. Retry And Result Reduction

Lifecycle and Manager callers share the runtime classifier and an evidence epoch.
One failed owner epoch produces at most one bounded recovery attempt until a
meaningful state change occurs. Transport failure, startup, stale recovery,
prerequisite failure, and persistent invalid evidence remain distinct result
codes. `Needs attention` is emitted only after the bounded recovery path is
exhausted or evidence is ambiguous; it is not used for the normal startup
window.

One-shot materializer/coordinator fallback is restricted to a proven bootstrap
case with no live or ambiguous owner. A generic `SUPERVISOR_UNREACHABLE` result
must not authorize a second command owner.

## Safety And Non-Goals

- Never stop an external MCP client, Codex process, Unity process, or unrelated
  process.
- Stop only a Package-owned child whose executable, argv, process-start identity,
  project/runtime, and owner epoch all match the authenticated evidence.
- Preserve immutable instance/current-pointer, lease, reparse, path, transaction,
  rollback, and unrelated-config boundaries.
- Do not redesign the selected instance/control layout or build the full v0.3
  Supervisor/Bridge queue promised for later slices.
- Do not add global MCP registration or a machine-global daemon.
- Do not rewrite a published generation in place. If the current unpublished
  Coordinator payload must change, refresh its manifest/hash closure once; if
  the bytes have already been released or consumed as immutable evidence, use a
  declared next-generation transition.
- Do not backport this work to `v0.2.x`.

## Focused Acceptance

The deterministic test set covers risk categories rather than a full state
Cartesian product:

1. Missing state/lock starts exactly one Supervisor.
2. State written before pipe listen remains `STARTING_OWNED`, not a terminal
   failure.
3. Dead Supervisor PID with stale state/lock is recovered automatically.
4. PID reuse, wrong executable, wrong argv, invalid JSON, reparse path, and
   unavailable identity never signal or delete the wrong process/evidence.
5. Two concurrent starters produce one owner and one Coordinator/Provider.
6. Repeated readers and writers of state JSON produce no `EPERM` loss, partial
   document, or false terminal status.
7. Supervisor loss during an admitted materializer or watcher operation does
   not duplicate the child and converges from durable evidence.
8. Coordinator/provider/adapter child recovery requires exact process-start and
   command identity; an unrelated sentinel remains alive.
9. A failed evidence epoch does not create an `Upgrade`/`Probe` retry storm;
   changed evidence permits one new attempt.
10. Manager state is `Starting` during bounded recovery and becomes
    `Needs attention` only after recovery is exhausted.

## Validation Order

Per slice, run only L0 syntax/compile and the affected deterministic harness.
After code freeze, run once:

- Supervisor and Coordinator focused Node harnesses;
- PowerShell/JSON/package boundary and hash-closure checks;
- the affected Unity EditMode subset, then one fresh full EditMode pass;
- one fresh local cold-start/Play and Domain Reload integration pass.

Real Codex Desktop tool injection, released-artifact acceptance, and
third-party Package-only paths remain `DEFERRED` until their environments are
available. No old PASS result substitutes for those gates.

## Implementation Snapshot

The current source snapshot implements the shared Supervisor owner evidence,
strict runtime classification, Windows-safe durable JSON publication, stale
takeover claim, operation single-flight and crash reattachment, authenticated
shutdown, and explicit one-shot bootstrap authorization. Watcher commands keep
the prerequisite-gated Editor lease before entering the Supervisor maintenance
lane. A missing child identity after a Supervisor crash is terminal and cannot
launch a replacement mutation.

Focused source-tree evidence covers Supervisor syntax and the deterministic
Supervisor harness, Package boundary/hash closure, PowerShell parser checks,
the package C# compile harness, and `git diff --check`. Fresh Unity Play/Domain
Reload, real Codex Desktop tool injection, released artifacts, and third-party
Package-only acceptance remain separate `BLOCKED`/`DEFERRED` gates until they
are actually executed.

## Exit Criteria

This task is complete only when the owner classifier, publication contract,
stale takeover, operation recovery, and bounded retry behavior are implemented
and their focused tests pass. A local source snapshot with a healthy-process
reconnect test alone is insufficient release evidence.
