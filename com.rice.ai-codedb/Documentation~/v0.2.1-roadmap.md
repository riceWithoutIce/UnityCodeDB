# UnityCodeDB v0.2.1 Roadmap

Status: approved for implementation; not yet implemented.

## Summary

Problem: the current project wrapper and registration flow can resolve a
relative Unity root from the wrong client working directory. Runtime status is
also inferred largely from file existence, while opening the Manager or an MCP
wrapper may start backend work. The service lifecycle is therefore not yet
owned by the Unity Editor in a way users can predict.

Decision: make the Unity Editor the only owner of the project CodeDB backend
lifecycle. Keep one project coordinator and one Provider/adapter backend per
Unity project, allow multiple Editor sessions to share it through leases, and
stop that project's backend after the last valid Editor lease disappears.
Manual enablement remains a persistent user preference, independent from the
current running state.

This is a correctness and lifecycle release. It does not expand the public MCP
navigation surface beyond the currently reviewed bounded tools.

## Candidate Matrix

| Candidate | Editor shutdown | Same-project multi-Editor | Manual disable | Main risk | Decision |
| --- | --- | --- | --- | --- | --- |
| Keep wrapper-triggered Ensure and one-shot fallback | Backend may outlive Unity | Ownership is implicit | Wrapper can restart work | Current behavior violates the desired lifecycle | Reject |
| Give each Editor an exclusive child backend | Parent exit can stop its children | Closing one Editor can kill shared work | Predictable per process | Cannot safely share one project backend | Reject |
| Extend the project coordinator with Editor session leases | Last lease stops the backend | All sessions share one backend | Desired state remains persistent | Requires a versioned lease and status protocol | Approve |

## Product Contract

- Interactive Unity Editor sessions own backend demand. BatchMode, CI, and
  command-line build sessions do not auto-start CodeDB by default.
- After valid Setup, CodeDB is enabled by default and starts asynchronously
  with the Editor without blocking the Unity main thread.
- Closing Unity stops only that Unity project's backend. Different open Unity
  projects retain independent runtimes and processes.
- Multiple Editor sessions for the same canonical project share one
  coordinator. Closing one session does not stop the backend while another
  valid session remains.
- A persistent manual `Enabled / Disabled` preference is separate from the
  actual `Starting / Ready / Stopping / Stopped / Error` state.
- Normal Editor shutdown does not change the preference. A user-disabled
  project remains disabled across Editor restarts.
- MCP wrappers never become lifecycle owners. They do not call `Ensure`, do not
  start a one-shot Provider, and exit after the Editor project lease is gone.
- Project-level wrapper registration is the only formal MCP route. Global and
  direct-Provider registrations are legacy test or migration paths, not
  accepted production configuration.
- Opening or refreshing the Manager is a read-only observation and never starts
  or repairs a service implicitly.

## State Model

The versioned project status must keep these dimensions separate:

- desired state: `enabled` or `disabled`;
- Editor demand: `online` or `offline`, with active session count;
- backend state: `starting`, `ready`, `stopping`, `stopped`, or `error`;
- Provider and Shader adapter health;
- index freshness: `fresh`, `stale`, `building`, or `unknown`;
- MCP registration: `missing`, `invalid`, or `valid`;
- current package and host-payload compatibility.

Manager scripts and wrappers consume structured, schema-versioned JSON rather
than parsing human-readable log phrases. User-facing command failures include
stable reason codes such as `SERVICE_DISABLED`, `EDITOR_OFFLINE`, `STARTING`,
`SETUP_REQUIRED`, `UPDATE_REQUIRED`, and `STALE`.

## Scope

### Root And Registration Correctness

1. Add `cwd = "."` to the Editor MCP snippet and PowerShell registration draft.
2. Require exactly `cwd = "."` in project-config validation.
3. Derive the authoritative Unity root from the installed wrapper path. Treat
   `--root` as an equality assertion, not as the authority.
4. Validate canonical `Assets`, `Packages`, and `ProjectSettings` markers before
   creating a host-use lease or any runtime path.
5. Reject direct-Provider and user/global registration shapes in the formal
   validator and documentation.
6. Add outer-working-directory and wrong-root tests proving no outer `AIWork`
   path is created.

### Editor-Owned Lifecycle

1. Add an Editor lifecycle owner initialized without requiring the Manager.
2. Start backend work asynchronously after Editor initialization and report
   progress through status instead of a blocking progress operation.
3. Publish one session lease containing a random session id, PID, process start
   identity, canonical project identity, and heartbeat.
4. Preserve the session across Domain Reload and avoid treating assembly reload
   as Editor shutdown.
5. Remove a lease immediately on graceful quit. Reclaim crash residue through
   PID identity checks and bounded heartbeat expiry.
6. Stop the coordinator, Provider, and adapter after the final valid Editor
   lease disappears.
7. Migrate existing Pause state without re-enabling a project the user had
   explicitly disabled.

### Truthful And Non-Blocking Status

1. Remove Manager-side automatic `Ensure` calls.
2. Move external status checks off the Unity GUI thread and cache their latest
   bounded result.
3. Validate Provider compatibility and health instead of checking only that an
   executable file exists.
4. Validate the exact MCP section and values instead of treating
   `.codex/config.toml` existence as configured.
5. Validate index manifests, timestamps, file counts, and freshness instead of
   treating a manifest path as current.
6. Include desired state, actual state, freshness, registration, and active
   Editor session count in the Overview model.
7. Treat intentional Disabled as a valid neutral state, not as Needs Setup.

### Query And Diagnostic Correctness

1. Preserve the `regex` argument when routing C# Provider searches and add a
   deterministic regression test.
2. Return explicit stale and fallback reason codes rather than silent zero-hit
   results for unavailable or unsupported paths.
3. Report pure LF/CRLF differences as EOL drift.
4. Remove the unimplemented `Outline` capability claim from the current Manager
   profile, or derive displayed capabilities from the real wrapper tool list.

### Setup And Upgrade Contract

1. Select and document one supported Setup mode before release:
   - self-service Setup with an exact target preview and explicit one-time
     confirmation; or
   - administrator-provisioned Setup that clearly reports the missing managed
     prerequisite to normal users.
2. Do not require a normal user to hand-author an undocumented authorization
   JSON while presenting Setup as self-service.
3. When the package payload is newer than the installed host payload, do not
   auto-start incompatible tooling. Report `UPDATE_REQUIRED` and provide a
   controlled stop, sync, and preference-preserving restart path.
4. Keep Provider acquisition explicit unless its distribution and license allow
   a separately reviewed installer flow.

### Release Integrity

1. Update package, wrapper, coordinator, payload, manifest sequence, hashes, and
   changelog versions together.
2. Update user documentation to separate normal use from test, POC, smoke, and
   legacy fallback procedures.
3. Keep project-level runtime and MCP isolation as release-blocking checks.

## Acceptance

1. Starting from an outer repository directory cannot create an outer
   `AIWork`; an invalid root fails before all writes.
2. One interactive Editor starts one project backend without opening Manager.
3. Opening and refreshing Manager produces no process start, repair, or project
   mutation and does not block the GUI thread.
4. Two Editor sessions for one project reuse one coordinator and Provider PID.
5. Closing the first session keeps the backend ready; closing the last session
   leaves no project coordinator, Provider, adapter worker, or wrapper orphan.
6. Hard-killing Unity leaves recoverable leases and the backend self-stops after
   the validated recovery window.
7. Domain Reload and Enter Play Mode do not flap or duplicate the backend.
8. BatchMode does not auto-start CodeDB.
9. Manual disable survives Editor restart; normal shutdown does not change an
   enabled preference.
10. With Unity offline or CodeDB disabled, MCP cannot start a Provider and
    returns the expected structured reason.
11. Two different Unity projects run concurrently with distinct runtimes,
    state, pipes, indexes, and process ownership.
12. Project registration without `cwd = "."`, with a wrong wrapper root, or with
    a direct Provider command fails validation.
13. C# regex results match the direct Provider/`rg` acceptance baseline.
14. Package boundary, materializer, Node/PowerShell syntax, payload hash,
    Unity EditMode, and `git diff --check` validation pass.

## Delivery Sequence

1. Fix root/cwd validation and regex propagation with zero-write regressions.
2. Define the desired-state, Editor-lease, and structured-status schemas.
3. Add the asynchronous Editor lifecycle owner and coordinator lease watchdog.
4. Remove wrapper Ensure and one-shot Provider fallback.
5. Make Manager status read-only, asynchronous, and truth-based.
6. Tighten MCP registration and capability reporting.
7. Complete upgrade migration, release metadata, documentation, and full
   lifecycle acceptance.

## Out Of Scope

- New navigation tools such as tree, symbol, outline, callers, dependencies, or
  explore.
- Semantic context retrieval, bounded request batches, or package dependency
  indexing.
- A broad export API or global CodeDB daemon.
- Declaring `rg` unnecessary before the v0.3.0 acceptance suite passes.
