# v0.3.0 P1-C: Supervisor Lifecycle Ownership

Status: implementation snapshot; not release evidence.

## Purpose

P1-C keeps Unity as a thin lifecycle signal and cached UI client. Play and
Domain Reload cancel Unity-side maintenance admission, while one authenticated
project Supervisor continues to own the selected immutable instance,
coordinator, and Provider outside the managed domain.

## Lifecycle Contract

- entering Play cancels maintenance tokens but does not invalidate a healthy
  Bridge or terminate a Package-launched process;
- stable Play permits query-priority Supervisor reconnect while maintenance
  remains suspended;
- a Play-mode Domain Reload restores the prerequisite-gated Editor lease on a
  worker and reconnects to the existing Supervisor instead of launching a
  duplicate backend;
- leaving Play reconnects and retries a non-terminal product state; a cached
  same-Package `Ready` state does not force a materializer availability pass,
  while an uncommitted Package fingerprint change forces one convergence pass;
- the Package fingerprint remains pending across cancellation and Domain Reload
  until a reconcile returns a completed lifecycle result;
- compilation and assembly reload invalidate only managed IPC waiters and
  request epochs;
- final Editor exit queues lease deletion and an authenticated `shutdown`
  request without filesystem or pipe waits in the Unity callback;
- final shutdown never launches a missing Supervisor and binds the request to
  the expected Package lifecycle identity;
- after a previously healthy coordinator remains unavailable for the bounded
  grace period, the Supervisor retires itself so an abrupt Unity exit cannot
  strand the project daemon.

The Supervisor can request Stop only through its independently authenticated
Package-owned coordinator pipe. It never sends Stop or a process signal to an
external MCP client or unrelated process.

## Focused Evidence

- Node syntax passes for the Supervisor and its deterministic harness.
- `Tests~/test-codedb-project-supervisor.mjs` proves same-PID reconnect,
  unauthorized and wrong-lifecycle shutdown refusal, authenticated final
  shutdown, coordinator-offline self-retirement, activation handoff, and zero
  signal to a test-owned unrelated process.
- The package and focused test assemblies compile with zero C# errors; the test
  assembly also compiles with zero warnings.
- `Tests~/test-codedb-package-boundary.ps1` proves stable-Play reconnect,
  token-only lifecycle suspension, non-launching final shutdown, and the
  existing immutable Package boundaries.
- `git diff --check` passes.

Fresh Unity cold-start, immediate Play, Play-mode Domain Reload, compilation
reload, final Editor exit, Manager cache observation, real Codex Desktop tool
injection, concurrent same-project Editors, and third-party Package-only
acceptance remain `DEFERRED` until run in their respective environments.
