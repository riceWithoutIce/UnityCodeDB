# UnityCodeDB v0.3.0 Roadmap

Status: approved direction; starts from the selected instance/control contract
carried forward from the current v0.2.5 development snapshot. A published or
accepted v0.2.5 release is not a prerequisite. Deferred live lifecycle and
Discover Read validation are not treated as passed evidence.

## Summary

`v0.3.0` has two ordered workstreams. Runtime isolation comes first: Unity
becomes a thin lifecycle/UI Bridge over a project-local external Supervisor.
Bounded Discover Read then expands on that stable runtime. The query work cannot
be considered complete while Editor callbacks still own heavyweight runtime
maintenance.

The current project wrapper exposes only status, find, search, text-search,
context, and bounded read. That is enough for limited discovery, but not for
reliable symbol navigation, dependency tracing, overloaded caller analysis,
Unity package source inspection, or a normal workflow that no longer uses `rg`
for routine indexed-code work.

Decision: build the Supervisor on the reviewed immutable instance/control and
atomic activation contract selected from the current development snapshot; do
not redesign that storage or Package-handoff layer as part of the Supervisor
work. Each carried-forward contract must still pass the v0.3.0 runtime gates;
the snapshot is not release evidence. Then expand the project-owned wrapper
into a bounded Discover Read surface with explicit freshness and strict output
limits. The Supervisor remains project-local, never machine-global.

## Selected Instance/Control Contract

`v0.3.0` adopts these reviewed contracts as implementation inputs. Their
selection does not promote the unpublished `v0.2.5` snapshot to a release:

- `control/desired-state.json`, `current-instance.json`,
  `last-known-good-instance.json`, and `operation.json`;
- immutable `host/generations/<generation-id>/` and isolated
  `instances/<instance-id>/` layouts;
- candidate provision, initialize/tools/status/query verification, atomic
  activation, rollback, and asynchronous retired-instance cleanup;
- side-by-side first install, Package upgrade, Reinstall, and logical Uninstall;
- one serialized project operation, cached Manager progress, and bounded
  cold-start/immediate-Play behavior.

The v0.3 runtime line must not reintroduce in-place Repair or make old-instance
cleanup a prerequisite for selecting a verified new instance.

## Runtime Isolation Scope

1. Keep Unity's main-thread Bridge limited to lifecycle signals, resolved
   Package identity, UI rendering, confirmation, and in-memory event enqueue.
2. Connect through versioned asynchronous IPC to one project-local external
   Supervisor. Reconnect after Domain Reload without restarting a healthy
   backend.
3. Move status evaluation, indexing, refresh, cleanup, Provider/adapter work,
   and process lifecycle into a query-first queue with one heavy job at a time.
4. Expose stable `CORE_READY`, `STARTING`, `MAINTENANCE`, `DEGRADED`, `BLOCKED`,
   `STOPPING`, and `STOPPED` states. A valid stale index remains queryable; a
   missing index reports bounded startup instead of blocking Unity.
5. Treat compilation, asset updates, and Play transitions as scheduling inputs,
   not synchronous work. Final Editor exit stops only authenticated
   project-owned backends and never an external MCP client.
6. Make Manager a cached Supervisor client. Opening or repainting it performs no
   filesystem scan, process launch, hash, lock wait, or synchronous IPC.

Runtime acceptance requires Domain Reload reconnect, queue ordering,
stale/missing-index behavior, outage/fallback behavior, final shutdown ownership,
and instrumentation showing zero CodeDB filesystem, hash, process, lock,
synchronous IPC, or full-status work on Unity's main thread. The basic Package
handoff and cold-Play foundations are carried forward from the selected
instance/control contract; the stronger Supervisor and zero-I/O claims require
new v0.3 evidence.

## Candidate Matrix

| Candidate | Capability | Project isolation | Operational cost | Decision |
| --- | --- | --- | --- | --- |
| Keep the six-tool wrapper and routine `rg` fallback | Limited search/read | Strong | Lowest | Keep only as the current baseline |
| Use a global complete CodeDB service | Broad | Violates project ownership and runtime isolation | Shared hidden state | Reject |
| Keep heavyweight lifecycle work in Unity callbacks | Existing features | Project-local but Editor-blocking | Repeated startup and Play risk | Reject for v0.3 |
| Add one project-local external Supervisor over the v0.2.5 instance contract | Runtime isolation and scheduling | Strong | Moderate IPC/lifecycle work | Approve first |

## Hard Gates

| Gate | Result | Release condition |
| --- | --- | --- |
| Target environment support | Conditional pass | Every added operation must work through the existing Windows/Unity project wrapper. |
| Distribution path | Conditional pass | The Supervisor ships through the Package-owned project path; no global daemon or unsupported dependency is required. |
| Scoped generated data | Conditional pass | Project and dependency indexes remain separate, ignored, disposable, and versioned. |
| Ignore and isolation behavior | Conditional pass | Results cannot contain another project or an unapproved dependency path. |
| Security and filesystem effects | Conditional pass | All tools remain read-only, bounded, and fail closed outside reviewed roots. |
| Repeatable validation | Pending | The query corpus, freshness SLA, ambiguity cases, and no-`rg` workflow trial must pass. |
| Clear integration boundary | Pass | Bridge owns Unity signals/UI, Supervisor owns scheduling/lifecycle, Provider owns C# analysis, adapters own text languages, and the wrapper owns query policy, merging, and bounds. |
| Baseline advantage | Pending | Must beat the existing wrapper + `rg` workflow in completeness and task-level usability, not merely run successfully. |

## Product Contract

- All new tools remain project-level, read-only, and bounded.
- Project source and approved dependency source are reported as separate lanes.
- A result is never silently treated as complete when freshness, support,
  truncation, or symbol identity is uncertain.
- Ambiguous symbol navigation requires a definition path and line anchor.
- One MCP response remains capped at 64 KiB.
- A batch contains at most 10 read-only operations and obeys one aggregate
  output budget.
- `rg` remains the verification and explicit fallback baseline until every
  release gate passes.

## Scope

### Bounded Navigation Surface

1. Add bounded tree/list and glob operations for indexed paths.
2. Add symbol definition and file outline operations.
3. Add callers/references with `definition_path` and `definition_line`
   anchoring for overload and same-name disambiguation.
4. Add direct and bounded transitive dependency/include traversal.
5. Add a budgeted explore operation that composes ranked files, outlines,
   dependency hints, and focused source excerpts.
6. Keep broad graph export, shell, edit, remote, memory, and cross-project tools
   unavailable from the default profile.

### Context And Batch

1. Replace text-search-only context with candidates informed by symbols,
   dependencies, and semantic ranking.
2. Preserve explicit evidence explaining why each returned file is relevant.
3. Add a maximum 10-operation read-only batch with a 64 KiB aggregate response
   ceiling and per-operation error reporting.
4. Do not add implicit batching or hide individual tool failures.

### Freshness And Language Lanes

1. Guarantee query-time Shader/HLSL freshness or return `STALE` before serving
   an incomplete result.
2. Expose incremental adapter state, last successful update, source snapshot,
   changed-file counts, and rebuild reason.
3. Keep C# Provider and Shader/HLSL adapter results distinct before the wrapper
   performs bounded merge and deduplication.
4. Preserve rename, delete, line-ending, and transient-write diagnostics.

### Controlled Unity Dependency Lane

1. Resolve only packages pinned by the Unity project manifest and lock file.
2. Index approved package source in a separate version-keyed dependency lane.
3. Label every result as project source or dependency source.
4. Refresh dependency data only when the resolved package identity changes.
5. Keep arbitrary `Library/PackageCache` scanning, unrelated cached versions,
   and machine-wide package discovery out of scope.

### Explicit Result Semantics

Every unavailable or incomplete operation returns a stable reason such as:

- `STALE`;
- `UNSUPPORTED`;
- `TRUNCATED`;
- `AMBIGUOUS`;
- `OUT_OF_SCOPE`;
- `INVALID_ARGUMENT`.

A legitimate zero-hit result remains distinguishable from these conditions.

## Acceptance Corpus

Build at least 50 real project queries covering:

- exact text and regex;
- file name, list, and glob;
- symbol definition and file outline;
- overloaded and same-name callers;
- imports, dependencies, and Shader includes;
- C#, Shader, HLSL, CGINC, and Compute source;
- created, modified, renamed, and deleted files;
- project source versus controlled Unity dependency source.

## Runtime Release Gates

1. The Bridge and Manager perform no CodeDB filesystem, hash, process, lock,
   synchronous IPC, PowerShell/Node, indexing, or full-status work on Unity's
   main thread; instrumentation verifies the claim.
2. Domain Reload reconnects to the same healthy Supervisor and selected instance
   without duplicate backend startup.
3. Query-first scheduling preserves available queries during maintenance; heavy
   work serializes and defers across compile, asset update, and Play transitions.
4. A valid stale index remains queryable with explicit freshness. A missing
   index reports bounded `STARTING`/`CORE_READY` and builds in the background.
5. Supervisor outage uses only the reviewed confirmed one-shot instance fallback.
   Final shutdown stops authenticated project backends only and preserves every
   external MCP client.
6. Fresh local Unity and third-party Package-only acceptance cover the exact
   v0.3 preview. Unexecuted two-project/elevation matrices remain `DEFERRED`.

## Discover Read Release Gates

1. Exact text, file, and regex result completeness is 100% against the `rg`
   baseline for the acceptance corpus.
2. Modified indexed code is returned inside the declared freshness window, or
   the operation returns `STALE`; silent stale misses are release-blocking.
3. Anchored caller and dependency samples have no cross-symbol merge errors.
4. Every result remains inside the canonical Unity project or an explicitly
   approved dependency lane.
5. Common internal query p95 is at most 200 ms on the representative Unity
   corpus; multi-step navigation uses bounded batch to limit MCP round trips.
6. Context results include meaningful symbol/dependency/semantic evidence and
   outperform text-search-only context on the reviewed natural-language set.
7. Ten consecutive real code navigation or analysis tasks complete without
   routine `rg`, and independent baseline verification agrees with the result.
8. Only after all gates pass may the normal workflow prefer project CodeDB and
   permit `rg` solely for explicit fallback reasons.

## Delivery Sequence

1. Freeze the selected instance/control contract; do not redesign candidate
   activation or Package handoff in this line.
2. Establish the thin Unity Bridge, project Supervisor, versioned IPC, reconnect,
   and minimum `CORE_READY` startup.
3. Move lifecycle and maintenance into the serialized query-first queue; close
   stale/missing-index semantics and authenticated final shutdown.
4. Make Manager a cached Supervisor client and prove Unity-main-thread zero I/O
   with fresh local integration.
5. Run the runtime-isolation third-party preview acceptance.
6. Freeze the query corpus and `rg` comparison harness.
7. Add list/glob, symbol, and outline with strict schemas and bounds.
8. Add anchored callers and dependency traversal.
9. Add budgeted explore and explicit result reason codes.
10. Add semantic context and the bounded 10-operation batch.
11. Add Shader/HLSL query-time freshness, incremental observability, and the
    controlled Unity dependency lane.
12. Run performance, completeness, ambiguity, isolation, and ten-task no-`rg`
    acceptance before changing the formal usage rule.

## Out Of Scope

- Write, edit, shell, remote execution, memory mutation, or cross-project tools.
- Broad source or graph export bundles.
- Indexing every package cached on the machine.
- A global CodeDB service replacing project-owned wrappers.
- Redesigning the v0.2.5 instance layout, atomic activation, or Package handoff
  unless a demonstrated correctness defect requires a separately approved
  migration.
- Removing `rg` before the acceptance corpus and workflow trial pass.
